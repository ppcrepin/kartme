KartSquad · Comment ça marche techniquement

Architecture IT

Comment l'app est construite, où tu peux la tester à chaque étape, quels outils entrent en jeu et qui doit créer quel compte. Ce document est la référence — on le relit et on le met à jour à chaque nouveau lot.

1Les trois couches

Image mentale : un restaurant. La salle, la cuisine, les prestataires.

Le client — l'app
Expo · React Native
Ce que voient et touchent les utilisateurs : écrans, boutons, animations. Une seule base de code produit iOS + Android + Web. C'est la « salle » du restaurant. Elle ne stocke rien de sensible : elle demande tout au backend.
↓ demande / reçoit ↑
Le backend — la mémoire & les règles
Supabase
Le cœur du système : qui est inscrit, quelles courses, quels Elo. Il applique les règles (« seul l'admin saisit le classement ») et vérifie à chaque requête « as-tu le droit ? ». C'est la « cuisine + le coffre-fort ». Toute la sécurité anti-triche vit ici.
↓ s'appuie sur ↑
Les services annexes
Expo Push · PostHog · Hébergeur web
Les prestataires : notifications push (« ton Elo a bougé »), statistiques d'usage, hébergement du site web. On les branche au fur et à mesure, seulement quand on en a besoin.
Le point clé : le téléphone ne calcule jamais l'Elo lui-même et ne stocke rien de critique. Tout passe par Supabase qui vérifie les droits. C'est ce qui rend la triche difficile — on ne peut pas « bidouiller l'app » pour gonfler son classement.

2Le trajet d'une action

Exemple concret : un admin saisit le classement final d'une course.

📱 Appl'admin saisit l'ordre d'arrivée et valide
🔒 Supabasevérifie : es-tu bien l'admin de cette course ? → oui
💾 Supabaseenregistre le classement (immuable, horodaté)
🧮 Supabaserecalcule l'Elo de tous les participants (côté serveur)
🔔 Pushnotifie chacun : « ton Elo a bougé, +18 »
📱 Apptous les téléphones se rafraîchissent en temps réel

Le recalcul se fait dans la cuisine, jamais sur le téléphone. C'est la garantie anti-triche.

3Où tu peux tester l'app

Quatre façons, de la plus rapide à la plus « vraie ». On les débloque au fil de la roadmap.

1
Lien web Disponible maintenant
Un simple lien à ouvrir dans ton navigateur (ordi ou mobile). Rien à installer. Le plus rapide pour valider l'avancement à chaque lot. C'est le mode recommandé pour la phase actuelle.
2
Expo Go Bientôt
Tu installes l'app gratuite « Expo Go » (App Store / Play Store), tu scannes un QR code, et KartSquad tourne dedans sur ton vrai téléphone. Aucun compte développeur requis.
3
Beta build Phase beta
Une vraie app KartSquad installée via TestFlight (iOS) ou un lien Google Play (Android) : icône, notifications, rendu réel. Tu peux inviter des amis testeurs.
4
Production Lancement 🚀
L'app publiée sur l'App Store et le Play Store, + le site web, téléchargeable par tout le monde.

5Comment mon code arrive jusqu'à toi

✍️ Codej'écris et je commit
🐙 GitHubstocke le changement
🤖 CIrelance automatiquement les tests, le typage, le style
🚀 Déploiementsi tout est vert → mise en ligne automatique
🔗 Toinouveau lien web / nouvelle beta à cliquer

La CI (mise en place au lot 0.1) est le filet de sécurité : elle bloque tout changement cassé avant qu'il arrive chez toi. C'est ce qui te permet de valider sans tout revérifier à la main.

L'ordre logique des choses
1. Maintenant → lien web cliquable du shell (premier vrai test).
2. Ensuite → compte Supabase, quand on attaque comptes utilisateurs & base de données.
3. Plus tard → comptes Apple/Google + Expo, pour une app installable et des beta testeurs.
4. Au lancement → publication sur les stores.
